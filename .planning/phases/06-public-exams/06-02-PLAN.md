  <name>Task 1: Implement scripts/download_exam_pdfs.py</name>
  <files>scripts/download_exam_pdfs.py, .gitignore</files>
  <action>
    Write a downloader that:
      1. Parses SOURCES.md (markdown tables) for rows with INCLUDE=yes.
      2. Downloads each PDF into data/exam_pdfs/<exam>/<year_slug>.pdf,
         skipping files that already exist (idempotent).
      3. Uses a normal browser User-Agent, 30s timeout, exponential-backoff
         retries (3 attempts).
      4. After download, computes SHA-256 and writes a sidecar
         <pdf>.meta.json with {url, exam, year, sha256, bytes, license}.
      5. Prints a progress line per file and a final summary
         (downloaded / skipped / failed).

    Add `data/exam_pdfs/` to .gitignore (we don't commit raw govt PDFs;
    they're re-downloadable from the manifest).

    Avoid: do NOT parallelize aggressively (max 2 concurrent downloads).
    Government servers throttle. Do NOT follow redirects to non-original
    hosts — if a redirect lands off the original domain, log + skip that
    URL (it might be a third-party mirror we explicitly excluded).
  </action>

<task type="auto">
  <name>Task 2: Implement scripts/parse_exam_pdfs.py</name>
  <files>scripts/parse_exam_pdfs.py</files>
  <action>
    Build a PDF→Q&A extractor:

    1. Install `pdfplumber` if missing (`uv pip install pdfplumber`).
    2. For each PDF in data/exam_pdfs/, walk pages and extract text.
    3. Apply per-exam regex-based segmenters (heuristic — exam PDFs are
       not standardized):

       - JEE_MAIN / NEET: questions usually start with
         `Q.\s*\d+`  or  `\d+\.\s` and end at the next question or "Sol."
         Options A/B/C/D follow.
       - UPSC: similar; answer keys are typically a separate PDF — try to
         match by file name (e.g. `..._answerkey.pdf`).
       - GATE: numbered questions, answers in a key PDF.

    4. Emit one JSONL row per detected question:
       {
         "raw_id":     "<pdf_slug>_q<n>",
         "exam":       "JEE_MAIN|NEET|UPSC|GATE",
         "year":       <int|null>,
         "question":   "<text including options>",
         "answer":     "<key letter if found, else null>",
         "source_pdf": "<relative path>",
         "source_url": "<from meta.json>",
         "license":    "<from meta.json>"
       }

    5. If extraction yields < 5 questions for a PDF, log a "low-yield"
       warning and continue (do not crash).

    6. CLI flags: `--limit-pdfs N`, `--exam EXAM` for testing.

    Write to datasets/exam-papers-raw.jsonl. Print final stats: PDFs
    processed, questions extracted, low-yield PDFs listed.

    Avoid: do NOT attempt OCR — that's a Phase 6.5 problem if we ever need
    it. Many JEE/NEET PDFs are text-based; some are scans. Scans = low yield
    = log + skip.
  </action>
  <verify>

    python scripts/parse_exam_pdfs.py --limit-pdfs 3

assert {'raw_id','exam','question','source_url','license'} <= set(rows[0]), rows[0]
print('OK', len(rows), 'sample exam:', rows[0]['exam'])
"
  </verify>
  <done>

  </done>
