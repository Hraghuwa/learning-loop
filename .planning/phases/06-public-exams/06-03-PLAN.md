<task type="auto">
  <name>Task 1: scripts/normalize_exam_corpus.py</name>
  <files>scripts/normalize_exam_corpus.py</files>
  <action>
    Read datasets/exam-papers-raw.jsonl and emit datasets/exam-corpus.jsonl
    using the SAME schema as math-corpus.jsonl / reasoning-corpus.jsonl
    from Phase 5:

      {
        "id":          "exam_<exam>_<raw_id>",
        "problem":     "<question text incl. options>",
        "answer":      "<key letter or text, or null if missing>",
        "solution":    null,
        "subject":     "exam",
        "subDomain":   "<exam>-<auto_tagged_topic>"  // e.g. JEE_MAIN-physics
        "source":      "<source_url>",
        "license":     "<license string>",
        "url":         "<source_url>"
      }

    SubDomain tagging:
      - JEE_MAIN  → cycle physics/chemistry/math by question position
        (papers have 30 each in order). Or use a keyword heuristic if the
        question text contains physics/chem/math keywords. Pick whichever
        is simpler — document choice in SUMMARY.
      - NEET      → physics/chemistry/biology
      - UPSC_CSE  → "general-studies" for everything (don't try to be clever)
      - GATE      → "gate-cs" / "gate-ee" etc. by paper code if available,
                    else "gate-general"

    Skip rows where `question` is < 30 chars or answer is null AND there's
    no obvious key file (low-quality extraction). Count and report skips.

    Write datasets/exam-corpus.stats.json with per-exam row counts.
  </action>
  <verify>

  <files>scripts/build_v1_1_corpus.py, datasets/v1.1-corpus.jsonl, datasets/v1.1-corpus.stats.json</files>
  <action>
    Build a merge script that:

    1. Reads in this order (Phase 5 + Phase 6 outputs):
         datasets/math-corpus.jsonl
         datasets/reasoning-corpus.jsonl
         datasets/exam-corpus.jsonl
         datasets/longform-corpus.jsonl    (passages — different schema)

    2. Concatenates rows from the first three into datasets/v1.1-corpus.jsonl
       (Q&A rows). Adds a `corpus_kind`: "qa" field.

    3. For longform passages, append them with `corpus_kind`: "passage"
       and pad missing fields (answer=null, solution=null). The downstream
       Phase 7 hygiene pass will keep them separate by `corpus_kind`.

    4. Re-IDs every row with a globally unique `id` if collisions are
       detected (prefix by source if needed).

    5. Computes datasets/v1.1-corpus.stats.json:
         { "total": N,
           "by_corpus_kind": {"qa": ..., "passage": ...},
           "by_subject":     {"math": ..., "reasoning": ..., "exam": ..., "longform": ...},
           "by_license":     {license_str: count, ...},
           "by_source":      {source_str: count, ...} }

    6. Print a one-screen summary of the stats at the end.

    Avoid: do NOT dedup yet (Phase 7 does that). Do NOT drop rows for
    quality reasons here — keep everything that has the required fields.
    Idempotent: re-running overwrites outputs cleanly.
  </action>
